Overview

VLN on the Fly allows a drone to navigate toward an object named in a language instruction, such as “go to the trash bin.” It uses camera images to locate the object, estimates its position from depth measurements, and plans and follows a path toward it. The navigation and control computations run onboard. We evaluated the system in indoor flight experiments with and without obstacles, using an external motion-capture system for position and orientation estimates.

Flight demonstration

How it works

The system separates finding the object, planning a path, and controlling the drone.

  1. Find the object. A quantized Qwen-3.5-2B vision-language model selects one of nine image regions. Depth measurements from that region give an estimated 3D goal.
  2. Plan a path. EGO-Planner builds a local map from depth measurements and produces a smooth path that accounts for obstacles.
  3. Follow the path. The pretrained RAPTOR policy converts the planned position setpoints into motor commands. It runs on the flight controller, without retraining for our airframe.

The vision-language model and planner run on a Jetson Orin NX. Keeping the stages separate lets us inspect the selected object region, estimated goal, and planned path when a flight does not reach its target.

Finding the requested object

The model selects an image region for the named object instead of predicting an exact pixel.

Flights around obstacles

We also tested the same system with obstacles between the take-off position and the requested object.

Experimental setup

Flights took place in a controlled indoor space, using a RealSense D435i depth camera and OptiTrack motion capture for position and orientation estimates.

Checks before flight

A goal is accepted only after three consecutive predictions select the same image region above the confidence threshold. The goal must also have valid depth and lie within the configured operating bounds. The planner checks the path against its local obstacle map before execution. When no goal passes the checks, the drone holds position and waits for a valid goal.

Limitations

These checks are not a general safety guarantee. Our evaluation used a single indoor motion-capture space and constrained flight altitude. The model sees only the current camera image, so it cannot locate an object outside the field of view and can mistake another object for an absent target. Limited depth range and invalid measurements can also affect the goal estimate. The paper describes the observed failures and experimental limits.
